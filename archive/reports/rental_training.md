# Budgeted PhoMT training on a rented RTX 4090

The launcher uses `Qwen/Qwen2.5-7B-Instruct` with BF16 rank-8 attention LoRA and TransferAdamW. It runs one supervised epoch on 3,800 disjoint pairs, exports the dense SFT base, then runs one paired GRPO epoch on 950 pairs. Both stages train in both directions, use the existing training-only augmentation, and validate on all 500 directional development examples. Final RL testing covers 7,000 translations, 3,500 each way, if quota permits.

The source cap is 512 tokens and the target cap is 128. The local tokenizer audit found 14 of 7,600 clean SFT target views and two of 1,900 clean RL target views above 127 tokens. Augmented concatenations can be longer. SFT uses learning rate 1e-4; RL uses 5e-6. Both stages use 100 warmup steps. GRPO uses two candidates and two optimizer updates per rollout, with the configured 70% COMETKiwi / 30% BLEU reward. COMETKiwi runs on CPU to reserve GPU memory for the 7B policy.

`scripts/train_bilingual_rental.py` verifies dataset SHA256 hashes and caches the public Qwen policy, tokenizer, and COMET encoder before training. The gated COMET checkpoint is supplied as a local model artifact. The process restarts with Hugging Face/Transformers offline mode enabled after cache validation. Dataset/model revisions and hashes are recorded in `cache_manifest.json`.

W&B logging uses the project **`Machine Translation`**, authenticated locally with `WANDB_API_KEY`. SFT and RL have separate runs in one group. The rental logs offline; `scripts/relay_wandb.py` publishes downloaded training/reward/validation/test metrics and cumulative phase timings from the local workstation. Checkpoints are saved every 100 optimizer steps and backed up locally, with the best development checkpoint kept separately. API keys and checkpoint weights are never sent from this workstation to the rental or W&B, respectively. No API key is placed in Hydra overrides, checkpoint hyperparameters, or source/data archives. Code and Git auto-upload are disabled. Metrics are collected approximately every two minutes; initial model-cache downloads can delay subsequent relay updates.

`RentalGuard` checks an external STOP file and a wall-clock deadline between training, validation, and test batches. Quota interruptions during fit save `checkpoints/interrupted.ckpt` with optimizer state for local backup. Interrupting final testing preserves existing fit checkpoints, avoiding a checkpoint that mixes reloaded best weights with the last optimizer state. Local tests cover deadlines, stop files, a real optimizer checkpoint/resume, both stage configurations, metrics-only relaying, and stripping credentials from SSH environments.

The local supervisor, `scripts/watch_vast_training.py`, periodically downloads checkpoints/reports, caches checksummed foundation/encoder snapshots, and preserves the exact merged SFT base needed for RL resume. Original source/data/COMET artifacts remain locally available. Before destroying an instance after completion or quota stop, the supervisor verifies downloaded backups. A separate hard-deadline process enforces the rental cap if graceful shutdown or backup fails. Keep the local workstation and supervisor running for this billing safeguard; a local process cannot operate while its machine is powered off or disconnected.

The current launch has a **$10 total cap**, reserving $0.35 for transfer charges. Graceful stopping begins at approximately $9 of elapsed rental cost, or sooner if available credit falls below $0.60. The independent hard cutoff allows at most $9.65 of elapsed rental cost. These guards account for the selected hourly rate and observed credit; final provider settlement can differ from a simple rate calculation. No automatic balance top-up is performed.

If external dataset-upload approval is pending, a separate idle watchdog destroys the instance 30 minutes after creation. Actual PhoMT training starts only after that explicit approval. Creating an instance and caching public assets does not mean training has begun. Session-specific state, URLs, timestamps, token audit, watchdog PIDs, and local cache paths are kept under `logs/training_20261108/`.

After any quota stop, resume using the saved Lightning checkpoint, the same resolved model revision, data partitions, and optimizer configuration. For RL, restore the cached dense SFT base at the original base path or use a deliberately migrated checkpoint/config with an unchanged base identity. Exact augmentation-worker RNG streams are not restored by the current framework.
